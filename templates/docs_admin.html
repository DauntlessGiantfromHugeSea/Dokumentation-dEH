Anleitung für Admins

Verwaltung, Sicherheit, Akten-Export und Server-Betrieb.

← Übersicht
1. Initiales Setup
  1. Erster User wird beim Erststart automatisch zum Admin promoted.
  2. 2FA ist Pflicht. Beim ersten Login kommt der QR-Code, einmal mit der Authenticator-App scannen.
  3. Admin-PIN setzen: Klick auf deinen Namen oben rechts → Account-PIN (Pfad: /account/pin). Mindestens 4 Ziffern, nur Zahlen.
    Ohne PIN tauchst du im Entschlüsseln-Dialog nicht auf!
2. Benutzer verwalten

Topnav rechts → Zahnrad (/admin/users).

Anlegen

  • Benutzername + Voller Name + Passwort (mindestens 6 Zeichen, idealerweise einmalig vergeben — User soll es selbst ändern).
  • Rolle:
    • Voll (Lesen + Schreiben) — Standard-Helfer mit Zugang zu beiden Welten.
    • Nur Zentrale Erste Hilfe schreiben — kann nur eigene zentrale Berichte anlegen, kann Vorbehandlungen lesen, aber keine dezentralen Berichte schreiben.
  • Häkchen Administrator — orthogonal zur Rolle. Nur Admins können User verwalten und Adress-Daten freigeben.

In der Liste

  • Passwort-Aktion: setzt ein neues Passwort für den User (z. B. wenn er es vergessen hat).
  • Rolle ändern: Dropdown direkt in der Zeile.
  • Admin geben / entziehen: für andere User toggeln. Letzten Admin kann das System nicht löschen oder demoten.
  • 2FA aktivieren / deaktivieren: per User. Mit „deaktiviert" wird der User mit nur Passwort eingeloggt — bestehende Authenticator- Secrets bleiben erhalten und werden bei Re-Aktivierung weiter genutzt.
  • 2FA zurücksetzen: löscht das Authenticator-Secret. Beim nächsten Login wird neu eingerichtet (z. B. nach Handy-Verlust).
  • Löschen: User komplett entfernen. Ihre erstellten Berichte bleiben erhalten (nur die Autoren-Verknüpfung wird gelöst).
3. Veranstaltungen verwalten

Topnav rechts → Zahnrad → links Veranstaltungen.

  1. Name vergeben, z. B. „Camp 2026". Dieser Name erscheint im Dashboard, in Protokollen und in der Aktenansicht.
  2. Präfix laufende Nr. vergeben, z. B. C26. Neue Berichte bekommen dann laufende Nummern wie #C261, #C262.
  3. Beginn und Ende eintragen, damit die Veranstaltung später sauber zugeordnet werden kann.
  4. Bestehende Veranstaltungen kannst du direkt darunter bearbeiten: Name, Präfix, Datum und aktiv speichern.
  5. Pro User unter Veranstaltungen festlegen: sehen bedeutet, dass die Person das Dashboard und die Berichte dieser Veranstaltung sehen darf. neu anlegen erlaubt zusätzlich neue Triage-Einträge und Protokolle in dieser Veranstaltung.

Admins sehen automatisch alle Veranstaltungen und dürfen überall anlegen. Oben in der Topbar kann zwischen den erlaubten Veranstaltungen gewechselt werden.

Veranstaltungs-Report

  1. Topnav rechts → Zahnrad → links Veranstaltungen öffnen.
  2. In der gewünschten Veranstaltungszeile auf Report klicken.
  3. Fehlende Angaben wie Ort, Veranstalter, Leitung und Helfer ergänzen.
  4. Bei Helfern kannst du vorhandene User auswählen oder freie Namen tippen.
  5. Der PDF-Export enthält reduzierte Kennzahlen, Triage-Zahlen, Top-Ersthelfer und die letzten Berichte.
4. Admin-PIN & Daten-Freigabe

Sensible Daten sind admin-only:

  • Notfallkontakt + Allergien-Details + Medikamente-Details auf der Patientenakte
  • Adresse + PLZ + Ort + Telefon + Krankenkasse im zentralen Notfallprotokoll

Helfer (Voll oder zentral_writer) sehen nur die Indikatoren (ja/nein/ unbekannt) bzw. den Hinweis „vertraulich". Mit dem Entschlüsseln-Button öffnen sie eine PIN-Eingabe:

  1. Helfer klickt Daten entschlüsseln (Admin-PIN).
  2. Dropdown zeigt alle Admins mit gesetztem PIN. Du wählst dich aus.
  3. Du tippst deine PIN.
  4. Bei Erfolg erscheinen die Daten kurzzeitig inline. Audit landet in emergency_unlocks — sichtbar in der Akten-Export-Vorschau.

Wenn ein Helfer beim Entschlüsseln „kein Admin mit PIN" sieht — bitte deine PIN auf /account/pin setzen.

5. Akten-Export
  1. Patientenakte öffnen (/patients/<ID>).
  2. Button Akte exportieren oben rechts.
  3. Vorschau-Seite zeigt, was im PDF landen wird:
    • Stammdaten + Notfallkontakt + Allergien/Medikamente (vollständig für Admins, nur Indikatoren für andere)
    • Alle dezentralen Berichte mit Hergang, Maßnahmen, Material, Kommentaren, Autor
    • Alle zentralen Notfallprotokolle mit Vitalwerten, Diagnose, Maßnahmen, Verlauf, Übergabe, Abschluss, Kommentaren, Unterschriften
    • Änderungs-Historie + Notfall-Datenfreigaben (Audit)
  4. Akte als PDF herunterladen — fertig. Footer auf jeder Seite mit Exporter-Name + Zeitstempel + Sicht-Modus.

Jeder Akten-Export wird in der Änderungs-Historie protokolliert („Akten-PDF exportiert · Admin-Sicht").

6. Berichte verwalten
  • Bearbeiten: jeder Voll-User kann eigene und fremde dezentrale Berichte bearbeiten. Zentrale Berichte sind eigentumsbasiert (Eigentümer + Admin).
  • Löschen erfordert das eigene Passwort als Bestätigung (nicht den PIN). Comments werden mit gelöscht (CASCADE).
  • PDF-Generierung des zentralen Notfallprotokolls ist admin-only. Helfer haben den Button nicht.
7. Server-Betrieb

Aktualisieren

cd ~/Dokumentation-dEH/Dokumentation-dEH && git pull
docker stop camp-doku && docker rm camp-doku
docker build -t camp-doku . && docker run -d --restart unless-stopped \
  -p 8000:8000 -v /srv/camp-doku:/data \
  -e SECRET_KEY="$(cat /srv/camp-doku/.secret 2>/dev/null || openssl rand -hex 32 | tee /srv/camp-doku/.secret)" \
  --name camp-doku camp-doku

Backup

Datenbank liegt im Volume /srv/camp-doku/app.db. Tägliches Backup:

cp /srv/camp-doku/app.db /srv/camp-doku/app.db.$(date +%F).bak

User per CLI anlegen

docker exec -it camp-doku flask create-user nico --full-name "Nico Test"
# zentral_writer:
docker exec -it camp-doku flask create-user lisa --role zentral_writer --full-name "Lisa Helferin"
8. Sicherheit / DSGVO
  • HTTPS ist Pflicht für echten Betrieb — über HTTP gehen Passwort + 2FA-Code im Klartext durchs Netz. Caddy + Subdomain ist 10 Minuten Arbeit.
  • SECRET_KEY muss zwischen Container-Neustarts stabil bleiben (im obigen Befehl per /srv/camp-doku/.secret persistiert).
  • Akten-PDFs enthalten medizinische Daten — sicher ablegen, nach Übergabe ans Krankenhaus/Eltern keine Kopie auf unverschlüsselten USB-Sticks o.ä.
  • Audit-Trail: Jede Daten-Freigabe (Notfallkontakt, Adresse) und jeder Akten-Export werden mit Wer/Wann protokolliert. Sichtbar in der Patientenakte und im Akten-PDF.
9. Troubleshooting
„kein Admin mit PIN" im Entschlüsseln-Dialog
Mindestens ein Admin muss auf /account/pin einen PIN setzen.
User kommt nach 2FA-Setup nicht durch
Server-Uhr und Handy-Uhr müssen synchron sein (TOTP toleriert nur ±30 s). Prüfen mit date auf dem Server.
Container wirft DB-Fehler beim Start
Volume /data nicht beschreibbar oder beschädigt. Prüfe Mount und ls -la /srv/camp-doku/. Backup zurückspielen, falls nötig.
Berichte mit fehlender Bericht-Nr.
Beim ersten Start nach dem Update werden alle Berichte automatisch mit globalen IDs versehen. Wenn ein Bericht trotzdem keine hat: Container neu bauen.
Gelöschten User wiederherstellen
Aus dem letzten Backup einspielen, dann neu anlegen — User-IDs werden nicht recycelt.
